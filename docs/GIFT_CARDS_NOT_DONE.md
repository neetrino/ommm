# Gift cards

Տեխնիկական առաջադրանքի (v1.0) բոլոր կետերը փակ են։ Բաց checkbox չկա։

Դասի քարտի գինը այդ դասի վերջին drop-in գինն է։ PDF-ը մեկ էջ է WinAnsi տառատեսակով. հայերեն հաղորդագրությունը ֆայլի մեջ չի մտնում, կոդը և անգլերեն ակտիվացման տողը մնում են։ Էջի «Տպել»-ը մնում է։

## 1. Ընդհանուր

- [x] Քարտի մնացորդը գումար է կամ կոնկրետ պարապմունքների քանակ (`FIXED_VALUE` / `FIXED_CLASS`)։
- [x] Կրեդիտով կարելի է վճարել փաթեթ, առանձին պարապմունք և բար։ Դասի քարտը ծածկում է համընկնող դասը, դրամային կրեդիտը՝ մնացած գումարը։
- [x] Զանգվածային թողարկումը միանգամից ծնում է N ունիկալ կոդ (`randomBytes`)։ Գնումը վերցնում է պատրաստ կոդը կամ ստեղծում է նորը։

## 2. Տիպ A — ֆիքսված գումար

- [x] Նվազագույն գումարը, նոմինալները և լռելյայն ժամկետը կարգավորվում են ադմինից (`StudioSettings`, Կարգավորումներ → Նվեր քարտեր)։ Լռելյայնը 30 000 AMD, 12 ամիս, 30 000 / 70 000 / 100 000 է։
- [x] Պատրաստի նոմինալներ և «այլ գումար»։ Կոճակները գալիս են `GET /gift-cards/policy`։
- [x] Մնացորդը հաշվին է մտնում կոդը մուտքագրելիս (`POST /gift-cards/redeem`)։ Գնումը `recipientId` չի դնում։

Մասնակի ծախսը մի քանի պատվերով և մնացորդի պահպանումը արված են փաթեթի, drop-in-ի և բարի համար։

## 2. Տիպ B — ֆիքսված պարապմունքներ

- [x] Քարտը տալիս է կոնկրետ պարապմունքի տեսակ և քանակ։ Ադմինի և խանութի ձևերում կա «Դասեր» տեսակը։
- [x] Դաշտերը կան. `classTypeId`, `classQuantity`, `balanceClasses`, `type = FIXED_CLASS`։
- [x] Ակտիվացնելիս պարապմունքները մնում են քարտին և ծախսվում են գրանցման ժամանակ։
- [x] Մասնակի ծախս մի քանի գրանցումով։ Չեղարկումը գրում է `REFUND` և վերադարձնում է դասերը։
- [x] Այլ տեսակի պարապմունք չի ծախսում այս կրեդիտը, քանի դեռ ադմինը չի միացրել `allowOtherClasses`։
- [x] Ադմինը կարող է թույլատրել այդ քարտը այլ դասի վրա (`PATCH /gift-cards/admin/cards/:id/other-classes`)։
- [x] Գործընկերային խմբաքանակը (օրինակ 50 քարտ × 1 դաս) թողարկվում է ադմինի ստեղծման ձևից. տեսակ Դասեր, քանակ 50։

## 3. Օգտագործման տրամաբանություն

### Քայլ 1 — քարտը հաշվին ավելացնել

- [x] Ստացողը մուտքագրում է կոդը վեբում և mobile-ում։
- [x] Կոդը կապվում է միայն եթե `recipientId` դեռ դատարկ է, և գրվում է `redeemedAt`։
- [x] Տիպ B-ի պարապմունքները մնում են `balanceClasses` դաշտում։
- [x] Նույն կոդը միաժամանակ երկու հաշվի վրա չի կապվում։
- [x] 8 սխալ փորձ 15 րոպեում կողպում է մուտքագրումը և գրում է `GIFT_REDEEM_LOCKED` audit։ 5 հաջող ակտիվացում նույն պատուհանում գրում է `GIFT_REDEEM_BURST`։

### Քայլ 2 — կրեդիտը վճարման ժամանակ

- [x] Փաթեթի checkout-ում դրամային կրեդիտը միանում է, ավելցուկը մնում է քարտին։
- [x] Drop-in վճարմանը կարելի է միացնել դրամային կրեդիտը (`useGiftCredits=true`)։ Լրիվ ծածկը բանկ չի բացում։ Վերադարձը քարտին է վերադարձնում այդ մասը։
- [x] Բարի կատալոգ (`BarProduct`) և `POST /payments/checkout/cart`։ Մեկ վճարման մեջ կարող են լինել փաթեթ, դաս և բար։ Դասի կրեդիտը զրոյացնում է դասի գինը, դրամային կրեդիտը ծածկում է մնացածը։ Զրո մնացորդը կատարվում է անմիջապես։ Վերադարձը վերադարձնում է դրամը և դասերը։
- [x] Դրամային դուրսգրումը ատոմար է (`updateMany`, մինչև 3 փորձ)։ Ժամկետ ունեցող քարտերը ծախսվում են առաջինը, ժամկետ չունեցողները՝ վերջում։ 50 քարտի սահմանաչափ չկա։
- [x] Ամեն ակտիվացում, դուրսգրում, վերադարձ, ճշգրտում և ժամկետ գրվում է `GiftCardTransaction` մատյանում։

## 4. Տվյալների մոդել

- [x] `type`, `classTypeId`, `classQuantity`, `balanceClasses`, `redeemedAt`, `allowOtherClasses`։
- [x] `gift_card_transactions` աղյուսակ. կոդ, օգտատեր, պատվեր, գումար կամ դաս, ժամ, վերջնական մնացորդ։ Ակտիվացումը `ISSUE`/`REDEEM` է, վերադարձը `REFUND`։
- [x] Ադմինի խմբաքանակը միանգամից թողարկում է կոդերը նույն `batchId`-ով։
- [x] Ժամկետանց քարտը ստանում է `EXPIRED` և այլևս չի ծախսվում։ Create-ի ժամանակ ժամկետը միշտ 12 ամիս է, ձեռքով չի գրվում։

## 5. Գնում գնորդի կողմից

- [x] Գնորդը ընտրում է գումար կամ դաս։ Դասի գինը վերջին drop-in գինն է, բազմապատկած քանակով։
- [x] Առաքում. email / WhatsApp / տպել։ Email-ը կարելի է հետաձգել. cron-ը ուղարկում է այդ օրվանից հետո։
- [x] PDF. `GET /gift-cards/me/:id/pdf`։ Քարտի էջում կան «Ներբեռնել PDF», «Տպել» և WhatsApp։
- [x] Վճարումից հետո քարտը կապված չէ հաշվին, մինչև կոդը մուտքագրվի։ Ստացողը կարող է լինել անդամ, անուն/email, կամ ոչ ոք. կոդը մնում է գնորդի մոտ։
- [x] Email-ում կա ակտիվացման հրահանգ. մտիր հաշիվ կամ գրանցվիր, մուտքագրիր կոդը։

## 6. Ադմին և հաշվետվություն

- [x] Խմբաքանակի թողարկված քարտեր, կոդով որոնում, CSV, մեկ քարտի ժամկետ, դրամային և դասային մնացորդ, մեկ քարտի անջատում։
- [x] Կոնվերտացիա դաս ↔ գումար այդ դասի drop-in գնով։ Ամբողջ դաս չլինող մնացորդը մնում է գումար։
- [x] Վերադարձ. փաթեթ, drop-in և զամբյուղ/բար։ Gift մասը վերադառնում է քարտին (`REFUNDED` / `FAILED`)։
- [x] Անձնական էջում գործարքների ցանկ կա։ Mobile-ում կա կոդի մուտքագրում։
- [x] Վաճառված և ակտիվացված քարտերը առանձին են (`redeemedAt`)։ Breakage-ը ժամկետանց չօգտագործված դրամային մնացորդն է (`breakageCents`)։

## 7. Որոշված կանոններ

- [x] Նվազագույնը, նոմինալները և լռելյայն ժամկետը ադմինի կարգավորումից են։
- [x] Gift կրեդիտով կարելի է վճարել փաթեթ, պարապմունք և բար։
- [x] Պարապմունքների քարտը այլ տեսակի վրա ծախսվում է միայն ադմինի `allowOtherClasses` թույլտվությամբ։
- [x] Մի քանի քարտ. սկզբում ամենամոտ ժամկետը, ժամկետ չունեցողները վերջում։

Չօգտագործված գնված քարտի գումարը գնորդին հետ չի վերադարձվում (`Gift card purchases are non-refundable`)։
